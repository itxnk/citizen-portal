System

Architecture

Browser → Frontend :5000 → Gateway :8000
    ├── User Service :8001 → PostgreSQL (users)
    ├── Records Service :8002 → PostgreSQL + Redis cache
    └── Notification Svc :8003 → PostgreSQL + Redis pub/sub

Each service: Deployment · HPA · ClusterIP · ServiceMonitor → Prometheus → Grafana

HPA Auto-Scaling Demo (CPU Stress)

Trigger CPU-intensive prime calculation on the Records Service to watch the HPA scale from 2 → 15 replicas.

Load Test Commands

Watch HPA in a separate terminal:

watch -n2 "kubectl get hpa,pods -n desc-app --no-headers | column -t"

Run k6 load test:

# Full ramp (0 → 200 VUs over 13 min)
export BASE_URL=http://$(kubectl get ingress -n desc-app -o jsonpath='{.items[0].status.loadBalancer.ingress[0].hostname}')
k6 run --env BASE_URL=$BASE_URL load-testing/k6/load-test.js

# Demo spike (0 → 300 VUs in 30s)
k6 run --env BASE_URL=$BASE_URL load-testing/k6/stress-test.js
